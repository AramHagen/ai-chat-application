Introduction
1–2 min

A full-stack AI chat application where users can sign up, sign in, and have real-time conversations with an AI assistant — similar to ChatGPT or Claude.

Key talking points

Both frontend and backend are written in TypeScript — gives type safety, better tooling, and catches errors at compile time instead of runtime

Two separate projects: server (API) and client (UI), deployed independently

The AI responses are powered by Groq — a fast open-source LLM API

2
Project Structure Overview
1 min
ai-chat-application/
├── server/ ← Node.js + Express API
└── client/ ← Angular frontend

Two separate projects, each with their own package.json, TypeScript config, linting, formatting, and test suite. They communicate over HTTP.

3
Server — Backend
4–5 min
Node.js Express TypeScript MongoDB Mongoose Groq AI JWT bcrypt
server/src/
├── index.ts ← entry point, starts the server
├── app.ts ← Express setup, middleware, routes
├── config/
│ ├── db.ts ← connects to MongoDB Atlas
│ └── groq.ts ← sets up Groq AI client
├── models/
│ ├── User.ts ← name, email, passwordHash
│ ├── Chat.ts ← chat session belonging to a user
│ └── Message.ts ← role (user/assistant) + content
├── controllers/
│ ├── authController.ts ← signup & signin logic
│ ├── chatController.ts ← create, list, delete chats
│ ├── messageController.ts ← send → Groq AI → save response
│ └── feedbackController.ts ← thumbs up/down on messages
├── routes/ ← defines API endpoints
└── middleware/
└── auth.ts ← verifies JWT, protects routes

Key talking points

MVC pattern — routes → controllers → models, each layer has one responsibility

JWT authentication — after login a token is issued; every protected request must include it in the header

bcrypt — passwords are hashed before saving, never stored as plain text

Groq AI — message is sent to the AI, response is saved to MongoDB and returned to the client

Unit tests in __tests__/ covering controllers and middleware

4
Client — Frontend
4–5 min
Angular 21 TypeScript Tailwind CSS Angular Signals RxJS
client/src/app/
├── app.routes.ts ← /signin, /signup, /chat
├── models/ ← TypeScript interfaces: User, Chat, Message
├── guards/
│ └── auth-guard.ts ← redirects to /signin if not logged in
├── interceptors/
│ └── auth-interceptor.ts ← auto-attaches JWT to every request
├── services/
│ ├── auth/
│ │ ├── auth-api.service.ts ← HTTP calls (signup, signin)
│ │ ├── auth-store.service.ts ← holds user/token + localStorage
│ │ └── auth-facade.service.ts ← single interface components use
│ └── chat/ ← same 3-layer pattern
└── components/
├── signin / signup ← authentication pages
├── chat/ ← main container, connects everything
├── sidebar/ ← conversation history list
├── chat-header/ ← title + sign out button
├── message-list/ ← messages + typing indicator
├── message-item/ ← single message bubble
└── chat-input/ ← textarea + send button with spinner

Key talking points

Angular Signals — modern reactive state, components update automatically when data changes

3-layer service pattern (API → Store → Facade) — HTTP logic, state, and UI concerns are fully separated

Auth guard — route-level protection, unauthenticated users are redirected automatically

HTTP interceptor — JWT token is attached to every outgoing request automatically

Loading state UX — send button shows a spinner and textarea is disabled while waiting for AI response; animated typing indicator shown in message list

5
CI Pipeline — GitHub Actions
1–2 min

A CI (Continuous Integration) pipeline in .github/workflows/ci.yml runs automatically on every push to main or development. It runs two parallel jobs — one for the server and one for the client — each with three steps:

Step Command What it checks
Lint npm run lint ESLint — catches bad code patterns
Format npm run format:check Prettier — ensures consistent code style
Unit Tests npm test Jest — verifies all tests pass

Key talking points

If any step fails, GitHub shows a red ✗ on the commit — you can't accidentally merge broken code

This is standard practice in professional software teams

6
Deployment
1–2 min

Railway — hosts both the frontend and backend as two separate services, auto-deploys on every push to main

MongoDB Atlas — cloud database, connected via the MONGO_URI environment variable

Secrets (API keys, JWT secret, DB password) are stored in Railway Variables — never committed to git

Frontend — Angular app is compiled to static files and served with serve inside a Docker container

Backend — runs as a Node.js process, compiled from TypeScript to JavaScript before starting
